# LumiRSS 2.0.1 · R2｜400 项修复 + 400 项新增

本文件是**候选工作目录**，不是对当前项目发现了 400 个缺陷的断言，也不是已完成报告。执行规则以 `MASTER.md` 为准。

## 计数与延续

本次“升级为 400+400”指 2.0.1 的累计交付目标：旧 FIX/NEW-001…200 延续，新补充 201…400。旧 worktree、提交、测试和有效证据必须接管，不能全删重做。原任务中只有盘点、审计、安装或确认“本来就正确”的项不得占修复额度。FIX-191/192/200 已把这种歧义改写为可验证的缺陷结果，旧原文保存在 `tasks.json`。

开始时逐项对照 release/2.0.1、已合入提交、运行中的 worktree、历史台账和真实界面。不存在的缺陷记 BASELINE_OK，已有功能记 ALREADY_EXISTS；**保留原候选及判定，再在同 ID 下登记替代项、理由和审批**。替代前先搜索全体 800 项及历史已发布功能，不能重命名旧功能或把一项拆成几个按钮。

## 每条默认的验收条件

**FIX：** 有一个明确可复现的失败条件、实际修复提交、有效回归测试及独立审查。视觉问题另有同条件前后截图和真实操作。原有大范围检查必须落到唯一根因；同一根因修正多个位置仍只计一次。没有找到足够真实缺陷时如实报告缺口，不制造问题。

**NEW：** 有当前版本原本没有的用户结果、可达入口、完整操作、状态变化或可检查产物；需要持久化的刷新后仍在，需要授权的有 A/B 隔离测试。后端字段、仅 tooltip、测试用例、格式美化、不能工作的按钮均不算新增。原有模块的独立新工作流可以计数，单纯修好原功能不可以。

每条描述中的动作和结果同时构成该项专项验收。自动 ID/标题检查不证明语义无重复；执行前和交付前分别由独立审查者复核。

## 读取方式

按领域读取一批 5–15 项，而不是每个 Agent 复制全部 800 项。`tasks.json` 是本任务包的机器可读候选源；执行现场只保留一个权威台账，勿再维护几份相互漂移的完成表。
